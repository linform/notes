# Markdown 日常笔记使用手册

> 适用环境：Windows + VS Code + MkDocs Material + GitHub Pages  
> 本文位于项目的 `docs/Markdown使用说明.md`，可从网站左上角的三横菜单访问。  
> **阅读方法**：每节先看 Markdown 写法，再看说明。带有「需要额外配置」的语法目前不一定能在你的网站中按预期显示。

---

## 0. 先记住这 6 件事

1. **笔记文件使用 `.md` 后缀**，放在项目的 `docs/` 文件夹中。
2. 标题用 `#`，加粗用 `**文字**`，列表用 `-`，链接用 `[文字](地址)`。
3. 数学公式：行内用 `$...$`，独立公式用 `$$...$$`。
4. 图片建议放入 `docs/images/`；使用**相对于当前 Markdown 文件**的路径引用。
5. 在 VS Code 中保存（`Ctrl + S`）后，MkDocs 本地网页会自动更新；后台脚本会定时将笔记同步到 GitHub。
6. **GitHub 仓库是公开的，`docs/` 下的文件会自动公开**。实验原始数据、尚未发表的研究材料、账号或个人敏感信息不要直接放入公开笔记。

---

## 1. 标题与文档结构

推荐一篇笔记只有一个一级标题，以下用二级、三级标题组织内容。

~~~markdown
# 固体物理笔记

## 第一章 晶体结构

### 1.1 布拉维格子

#### 基本定义

正文写在这里。
~~~

渲染后，MkDocs 会根据标题生成页面右侧目录；左侧导航由 `mkdocs.yml` 的 `nav` 控制。新增文章后，记得将其加入导航。

**建议：**

- `#` 后面留一个空格；其他标题同理。
- 标题级别尽量不要跳跃，例如不要从 `##` 直接跳到 `####`。
- 不要只为了让文字变大而滥用标题。

## 2. 常用文字格式

| 想实现的效果 | Markdown 写法 |
| --- | --- |
| **加粗** | `**加粗**` |
| *斜体* | `*斜体*` |
| ***粗斜体*** | `***粗斜体***` |
| `行内代码` | `` `行内代码` `` |
| 分段 | 两段文字之间空一行 |
| 强制换行 | 行末加两个空格，然后换行（或直接分段） |
| 分隔线 | 单独一行写 `---` |

例如：

~~~markdown
**定义：** 晶格是由空间中按平移对称规律重复排列的点构成的。

*注意：* 晶格点不一定等于真实原子位置。

运行命令 `mkdocs serve` 启动本地预览。
~~~

> **兼容性提醒：** 常见的 `~~删除线~~` 虽然被不少 Markdown 编辑器支持，但你当前的 MkDocs 配置尚未显式启用 `pymdownx.tilde`；不要依赖它在网站中的显示效果。

## 3. 列表与分点整理

### 3.1 无序列表

~~~markdown
- 晶格常数
- 晶面间距
- 倒易点阵
    - 倒易基矢
    - 第一布里渊区
~~~

### 3.2 有序列表

~~~markdown
1. 明确已知条件。
2. 写出基本公式。
3. 代入参数计算。
4. 检查单位与物理意义。
~~~

### 3.3 待办清单（需要额外配置）

~~~markdown
- [ ] 阅读论文
- [ ] 完成数据处理
- [x] 整理实验记录
~~~

上面的写法通常需要在 `mkdocs.yml` 的 `markdown_extensions` 中增加 `pymdownx.tasklist` 才能渲染为复选框。**当前网站尚未开启这一扩展**；如果不想改配置，暂时可用普通列表代替：

~~~markdown
- 待做：阅读论文
- 待做：处理数据
- 已完成：整理实验记录
~~~

## 4. 引用、分隔线与重点提醒

引用块以 `>` 开头，适合记录教材表述、论文原文或个人提醒。

~~~markdown
> 注意：实验结果需要区分相关性与因果关系。
>
> 关键结论应尽量标注数据来源。

---

这是下一个部分。
~~~

如果在笔记中摘录论文原文，建议紧跟作者、文章标题或 DOI，方便日后追溯。

## 6. 数学公式（已配置 MathJax） {#math}

这是科研笔记最实用的功能之一。你当前网站已配置 `pymdownx.arithmatex` 和 MathJax。

### 6.1 行内公式

~~~markdown
根据布拉格定律，$2d\sin\theta=n\lambda$。
~~~

效果：根据布拉格定律，$2d\sin\theta=n\lambda$。

### 6.2 独立公式

~~~markdown
$$
E=mc^2
$$
~~~

效果：

$$
E=mc^2
$$

### 6.3 科研中常用的 LaTeX 语法

| 功能 | 输入代码 | 说明 |
| --- | --- | --- |
| 上标 | `x^2` | $x^2$ |
| 下标 | `a_{ij}` | $a_{ij}$ |
| 分数 | `\frac{a}{b}` | $\frac{a}{b}$ |
| 根号 | `\sqrt{x}` | $\sqrt{x}$ |
| 求和 | `\sum_{i=1}^{N}` | $\sum_{i=1}^{N}$ |
| 积分 | `\int_0^L` | $\int_0^L$ |
| 偏导 | `\frac{\partial U}{\partial T}` | $\frac{\partial U}{\partial T}$ |
| 希腊字母 | `\alpha,\beta,\theta,\omega` | $\alpha,\beta,\theta,\omega$ |
| 向量 | `\mathbf{k}` | $\mathbf{k}$ |
| 文字正体 | `\mathrm{Li}` | $\mathrm{Li}$ |

### 6.4 多行对齐推导

推荐在独立公式环境中使用 `aligned`，用 `&` 标记对齐位置，用 `\\` 换行。

~~~markdown
$$
\begin{aligned}
F &= ma \\
  &= m\frac{dv}{dt} \\
  &= \frac{dp}{dt}
\end{aligned}
$$
~~~

### 6.5 材料与电池方向示例

**阿伦尼乌斯方程**：

~~~markdown
$$
\sigma = \sigma_0 \exp\left(-\frac{E_a}{k_B T}\right)
$$
~~~

**锂离子与化学式**：

~~~markdown
$
\mathrm{Li^+},\quad
\mathrm{LiFePO_4},\quad
\mathrm{LiNi_{0.8}Co_{0.1}Mn_{0.1}O_2}
$
~~~

**注意：** `\ce{...}` 属于 `mhchem` 扩展语法，你当前没有单独配置该扩展。因此写化学式时优先使用 `\mathrm{...}`、上标和下标。

## 7. 表格（已支持）

~~~markdown
| 电解液 | 常温表现 | 低温表现 |
| :--- | :---: | ---: |
| DME | 良好 | 85 |
| THF | 较好 | 90 |
| DBE | 较好 | 95 |
~~~

这里的数字仅用于演示表格布局，不代表真实实验数据。

- `:---` 表示左对齐。
- `:---:` 表示居中。
- `---:` 表示右对齐。

**注意：** Markdown 表格适合记录摘要数据，不适合存储大量原始数据。大型实验数据建议保留在 CSV 或 XLSX 文件中，在笔记里只写结果摘要和数据来源。

## 8. 链接与文献引用

### 8.1 普通链接

~~~markdown
[Materials Project](https://materialsproject.org/)

[访问我的笔记网站](https://linform.github.io/notes/)
~~~

### 8.2 笔记之间互相引用

假设你的目录结构：

~~~text
notes/
└── docs/
    ├── index.md
    ├── 固体物理.md
    ├── 晶体学.md
    └── 电池/
        └── 固态电池.md
~~~

在 `固体物理.md` 中：

~~~markdown
参见[晶体学笔记](晶体学.md)。

参见[固态电池笔记](电池/固态电池.md)。
~~~

在 `电池/固态电池.md` 中返回上一级：

~~~markdown
返回[固体物理笔记](../固体物理.md)。
~~~

MkDocs 会在构建时处理这些指向 Markdown 文件的相对链接。文件改名或移动后，记得同步修改其他笔记中的引用。

### 8.3 推荐的文献记录格式

~~~markdown
**参考文献**

- 作者，论文标题，期刊，年份，DOI：`10.xxxx/xxxxx`
- [论文原文](https://doi.org/10.xxxx/xxxxx)
~~~

DOI 示意文字只是占位符，正式笔记要替换成真实 DOI。

## 9. 插入图片（最重要的路径规则） {#images}

### 9.1 推荐目录

~~~text
notes/
└── docs/
    ├── 固体物理.md
    ├── images/
    │   ├── crystal.png
    │   └── xrd-pattern.jpg
    └── 电池/
        └── 固态电池.md
~~~

在根目录 `docs/固体物理.md` 中：

~~~markdown
![晶格结构示意图](images/crystal.png)
~~~

在子文件夹 `docs/电池/固态电池.md` 中：

~~~markdown
![晶格结构示意图](../images/crystal.png)
~~~

`../` 表示返回上一级目录。

### 9.2 图片路径常见错误

- 图片真实位置为 `docs/images/crystal.png`，但写成了电脑绝对路径 `C:\Users\...\crystal.png`：**发布网页后会失效**。
- 文件名大小写不一致：Windows 上可能看起来正常，GitHub Linux 构建环境中可能失效。
- 图片文件没有放入 `docs/`：可能不会被 MkDocs 一起发布。
- 路径里大量空格或特殊符号：容易增加链接维护难度。推荐文件名如 `xrd_pattern_01.png`。

### 9.3 图片与论文笔记

建议每张关键图片后用一句话标注：**图示内容、变量、主要结论、出处**。例如：

~~~markdown
![不同样品的 XRD 对比](images/xrd_pattern_01.png)

**图 1.** 不同样品的 XRD 图谱（数据来源：本人实验；处理方法：背景扣除后归一化）。
~~~

~~~text

│   ├── 固体物理/

│   │   ├── 电解液.md
~~~

## 12. VS Code 与 GitHub 日常使用流程

### 12.1 每天怎么写

1. 用 VS Code 打开项目根目录；首次使用先按仓库 README 创建 `.venv` 并安装依赖。
2. 在 `docs/` 下创建或打开 `.md` 文件；新文章同时加入 `mkdocs.yml` 的 `nav`。
3. 按 `Ctrl + S` 保存（如需减少手动保存，可在 VS Code 启用自动保存）。
4. 在本地网页查看最终排版；以运行终端显示的地址为准，你当前配置下通常是 `http://127.0.0.1:8000/notes/`。
5. 启用 VS Code 自动任务后，同步脚本仅在 `main` 分支每 60 秒检查一次，提交笔记并核验推送；GitHub Actions 检查通过后部署网站。分离 HEAD 或其他分支不会自动提交、推送。

在线地址：<https://linform.github.io/notes/>

**同步时间说明：** 60 秒是本地脚本的检查周期，不等于公开网页会在 60 秒内更新。远程部署还需要额外时间，并可能因网络、Git 冲突或 GitHub Actions 失败而延迟。

### 12.2 常用 VS Code 快捷键（Windows）

| 操作 | 快捷键 |
| --- | --- |
| 保存 | `Ctrl + S` |
| 搜索当前文件 | `Ctrl + F` |
| 全局搜索 | `Ctrl + Shift + F` |
| 命令面板 | `Ctrl + Shift + P` |
| 打开 Markdown 预览 | `Ctrl + Shift + V` |
| 预览到侧边 | 先 `Ctrl + K`，再按 `V` |
| 显示／隐藏终端 | <kbd>Ctrl</kbd> + <kbd>&#96;</kbd>（反引号） |

### 12.3 自动同步失败怎么办

先检查 VS Code 底部两个运行任务：

- `MkDocs: Start live preview`：本地网站构建是否成功。
- `Git: Automatically sync notes`：是否输出推送成功信息。

如果 Git 推送失败，不要直接强制推送或删除 `.git`。先检查终端报错。若远程和本地历史发生冲突，应先手动处理后再恢复自动同步。脚本会保留本地提交，但不会自动拉取或合并。

脚本只自动提交 `docs/` 和 `mkdocs.yml`。修改依赖、README、脚本或工作流后需要手工提交。终端确认推送完成后，还需到 GitHub Actions 检查部署结果。

## 13. 进阶扩展（当前尚未启用，可选）

你当前 `mkdocs.yml` 已支持：**表格、代码块、图片、数学公式、中文搜索、主题切换**。下面两种语法需要额外增加扩展。

### 13.1 待办复选框

在 `mkdocs.yml` 的 `markdown_extensions` 下增加：

~~~yaml
  - pymdownx.tasklist:
      custom_checkbox: true
~~~

之后可使用：

~~~markdown
- [ ] 阅读文献
- [x] 整理数据
~~~

### 13.2 提示框

在 `markdown_extensions` 下增加：

~~~yaml
  - admonition
  - pymdownx.details
~~~

即可使用：

~~~markdown
!!! note "实验提醒"
    正式测试之前记录温度、测试条件和样品编号。

??? warning "展开查看注意事项"
    确认数据备份之后再进行批量处理。
~~~

这些是**追加条目**，不要把已有的 `markdown_extensions` 内容删掉。修改 `mkdocs.yml` 后保存，先检查本地网页是否能够正常构建。

## 14. 常见问题速查

| 问题 | 检查方法 |
| --- | --- |
| 修改后网页没有变化 | 文件是否保存？MkDocs 任务是否在运行？ |
| 公式原样显示 `$...$` | 检查 `pymdownx.arithmatex`、MathJax 脚本和浏览器网络连接 |
| 图片不显示 | 检查图片是否在 `docs/` 中、相对路径和文件名大小写是否正确 |
| 网站没有新增文章 | 新 `.md` 是否在 `docs/` 下并加入 `nav`？是否已推送并完成 Pages 部署？ |
| GitHub 没更新 | 查看 `Git: Automatically sync notes` 任务输出 |
| 任务列表没变复选框 | 当前尚未启用 `pymdownx.tasklist` |
| 提示框语法未生效 | 当前尚未启用 `admonition`、`pymdownx.details` |
| 文章内容很长不好找 | 合理使用 `##`、`###` 标题，利用右侧目录 |
